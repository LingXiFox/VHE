# EXP-0027 — How many steps does the 16-channel VHE model need to reach 0.4x on a fixed 8-pair batch?

## 假设
EXP-0026 在 600 步时 total 为 0.530×，仍在稳定下降（spectral_convergence 0.8025 → 0.2951），说明瓶颈是步数预算而不是容量。lr 3e-3、同一固定 8 对 batch 下，2000 步内 total 会跌破首值的 0.4×；跌破的步数本身是要记录的量。

## 变量 / 对照组 / 数据划分
- 唯一变量：步数 600 → 2000（其余与 EXP-0026 相同：lr 3e-3、batch_size 8、channels 16、crop 1.6 s、seed 42、Adam、grad_clip 1.0、同一缓存前 8 对）。
- 对照组：EXP-0026 的 600 步曲线。
- 数据：`derived/aishell3-pairs/p2-train40x10-v2` 前 8 对固定；不评估泛化。

## 预注册通过/失败条件
1. 2000 步内存在某步 total ≤ 0.4 × 首步 total；记录首次跌破的步数。
2. 全程无 NaN/Inf，输出长度 == 输入长度。
3. 运行时间 < 5 min。
不满足 → 结论为「16 通道在 2000 步、lr 3e-3 下仍不能拟合 8 对」，记为 P2 阻塞项，下一步改容量或损失权重而不是继续加步数。

## 已知局限（运行前写下）
- 只看 total 会掩盖分项之间的权衡，必须同时报告 spectral_convergence / log_magnitude / periodicity。
- 单模板、8 对、单 seed；不涉及听音，也不代表泛化能力。
- 这一步只回答「管线能否过拟合」，不是训练目标本身的验收。

## 实际结果与主观听音
- 实跑 73.89 s（RTX 4090 Laptop，CUDA，FP32），2000 步，batch 8，lr 3e-3。
- total：step 1 **3.7401**；0.4× 阈值 = **1.4960**。
- **首次跌破阈值：step 1850（1.4535）**；step 1950 也低于阈值（1.4947）；step 2000 回到 1.5648（0.418×）。summary 记 best_total **1.4507**（0.389×，落在未记录日志的步）；日志内最低点是 1.4535@step 1850。
- 平台期：step 1400 之后 total 在 1.45–1.69 之间震荡，没有继续下降；最后 5 个日志点 1.551 / 1.453 / 1.523 / 1.495 / 1.565。
- 分项（step 2000）：spectral_convergence 0.1711（vs 首值约 0.86）、log_magnitude **1.2786**（vs 2.16）、periodicity 0.0367（vs 0.29）。
- 无 NaN/Inf，输出长度不变（判据 2 通过）；73.9 s < 5 min（判据 3 通过）。
- 日志：`logs/overfit8.log.jsonl`、`logs/overfit8.summary.json`。
- 主观听音：未做。

## 失败、负面发现、错误日志
- 判据 1 按字面（「2000 步内存在某步 ≤0.4×」）**通过**，但必须同时记下三点，否则会误导：
  1. 不是单调达标：step 2000 本身是 0.418×，高于阈值；
  2. 只是第一次碰到阈值，不能据此说「已收敛到 0.4×」；
  3. 平台由 log_magnitude 撑着：末步 log_magnitude 1.2786 占 total 的 **82%**，spectral_convergence 已降到 0.17、periodicity 0.037。
- 机制解读：log_magnitude 比较的是预测与真人参考的对数幅度谱。机械输入是给定的（不许改），模型只能在其上加残差；当残差修正到「与机械输入同样平滑」时，这一项就停在机械/真人频谱差的水平。也就是说 **1.45–1.5 很可能是该损失在固定 8 对上的地板**，继续加步数不会显著改善。
- 未做：更换损失权重、按频率加权、把 log_magnitude 换成其它保真项——都属于新实验，不能在本次里顺手改。

## 结论 / 下次实验
- 结论：管线能过拟合到 0.389×，但代价是 1850 步，且平台期由 log_magnitude 主导。P2 的「能过拟合小批次」判定项可以记为**有条件通过**（需要 1850 步才首次触及 0.4×，且末步高于阈值），不得写成「已充分过拟合」。
- 真正的问题转移到损失设计：log_magnitude 在固定 batch 上把 loss 钉在 ~1.45。下一步应当是消融损失权重（尤其 log_magnitude 的主导地位），并检查残差是否在改变音色，而不是继续加步数。
- 未做：听感、多 seed、dev 泛化曲线。
